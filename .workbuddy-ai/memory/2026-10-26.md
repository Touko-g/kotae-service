### 关键决策：为什么流式不走 StreamingHttpResponse

Django 4.0 的 `ASGIHandler.send_response` 里是 `for part in response:`（同步迭代，跑在事件循环线程）。
用 `requests` 读上游会阻塞整个 Daphne 事件循环 —— AI 生成 30 秒，Channels 群聊就冻 30 秒。
所以 `/api/ai/chat-stream/` 由 `ai/asgi.py` 的原生 ASGI 应用处理：读上游放线程、`asyncio.Queue` 回传、
`http.disconnect` 时置位停止标记。`backend/routing.py` 用 `AiHttpRouter` 把该路径摘出来，其余交回 Django。
已用本地假上游 + Daphne 实测：流式期间普通接口 418ms 返回，未被阻塞。

升级 Django 4.2 也能解决，但会牵动 channels 3.0.5 / drf-yasg / drf-api-logger，风险更高。

## 修复 requirements.txt 编码（部署阻塞）

## 部署要点（已确认的约束）

- Python **3.9**：依赖版本较旧（Django 4.0.5 / asgiref 3.5.2 / channels 3.0.5），3.10+ 可能装不上
- **必须 daphne 启动**（`backend.routing:application`）：群聊 WebSocket 与 AI 流式原生 ASGI 通道都依赖 ASGI，
  `backend.wsgi` 下 WebSocket 不可用、AI 流式退化为阻塞视图
- **Redis 必须跑在 127.0.0.1:6379**：`CHANNEL_LAYERS` 是硬编码的
- 反代：`/ws/` 需 Upgrade 头；SSE 需 `proxy_buffering off` + `proxy_read_timeout` ≥ 300s
- `.env` 目前只有 `secret_id` / `secret_key` / `EMAIL_HOST_PASSWORD`，**没有** `DJANGO_DEBUG` 与 `DJANGO_SECRET_KEY`
  → 不补的话生产会跑在 DEBUG=True + 硬编码 SECRET_KEY
- 换 `DJANGO_SECRET_KEY` 的连带影响：存量 JWT 全部失效；已保存的 AI Key 解不开（返回 `needs_reentry` 让用户重填）
- `db.sqlite3` 未被 git 跟踪，部署需单独上传或新建
- `static/` 被 git 跟踪且 `STATIC_ROOT` 指向同一目录，`collectstatic` 会让工作区变脏
- `manage.py check --deploy` 当前 6 条告警：HSTS / SSL 重定向 / SECRET_KEY / SESSION_COOKIE_SECURE /
  CSRF_COOKIE_SECURE / DEBUG

## 验证码邮件模板化（对齐站点主题）

原来 HTML 是拼在 `api/utlis.py` 的 f-string 里，配色用 `#EC1C24`、无响应式。改为模板渲染：

- `templates/email/base.html` — 骨架，取站点 light 主题 token：底色 `#F9FAFB`、卡片 `#FFFFFF`、
  主色 `#e41b23`、描边 `rgba(0,0,0,.9)`→`#1A1A1A`、圆角 18px、硬投影 `6px 6px 0`（站内 `.page-hero` 同款贴纸风）
- `templates/email/verification_code.html` — 场景无关，文案由 context 注入
- `templates/email/verification_code.txt` — 纯文本兜底（只发 HTML 会显著提高进垃圾箱概率）
- 布局全部 table + 内联样式：Outlook 不认 flex/grid，QQ 邮箱/Gmail 会丢 `<head>` 的 `<style>`；
  `<style>` 里只留响应式媒体查询（≤620px 卡片转 100%）
- `api/utlis.py`：`EMAIL_SCENES` 集中注册/重置两套文案（subject / scene_label / heading / intro），
  `send_verification_code_email(email, code, scene)` 用 `EmailMultiAlternatives` 发双版本；旧的 `send_email_mes` 已删除
- **顺带修掉**：`get_random_code` 原来混了 `string.punctuation`，验证码会出现 `< & "` 这类字符
  （邮件里要靠转义、用户也不好抄），改为 31 字符的字母数字表（去掉 0/o/1/l/I）
- 新配置：`DEFAULT_FROM_EMAIL`（`Kotae <邮箱>` 显示名）、`SITE_URL`、`EMAIL_LOGO_URL`，均可环境变量覆盖
- `common/tests.py` 新增 10 个用例（场景文案、双版本、内联样式/无 flex、绝对地址、字符集、兜底）
